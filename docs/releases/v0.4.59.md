# v0.4.59 — an empty workflow result is not a report

## Upgrade notes

From v0.4.58, pull and restart. No schema change, migration, or new setting.
Machine clients must now send non-whitespace content in either `body_md` or the legacy
`body_html` field. Existing reports, including previously stored empty rows, are left unchanged.

## Fixed

- The v1 ingest endpoint rejects a request when both report-body fields are absent, null, empty,
  or whitespace-only, instead of publishing a title-only blank page.
- A rejected bodyless re-ingest cannot erase the content of an existing report through the
  identity-key upsert path.
- A whitespace-only Markdown field no longer hides a valid legacy HTML body; the HTML-only
  compatibility path remains available, while meaningful Markdown remains authoritative.

## Validation

Regression coverage exercises omitted, null, empty, and whitespace-only bodies; protects an
existing report from a blank overwrite; and preserves Markdown-only, HTML-only, dual-body, and
whitespace-Markdown-plus-HTML ingestion. The full backend and frontend release gates pass.
