# v0.4.19 — the IP database form asks only what the source needs

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema change.

If you are behind a reverse proxy on Docker, read [v0.4.18](v0.4.18.md) first: the audit log records
the bridge gateway for every visitor until the gateway is named in `trusted_proxies`.
`docker-compose.yml` now carries the exact line, commented, with the command that finds your gateway.

## Fixed

**The picker showed a lone `.` instead of "automatic".** Choosing automatic submits an empty
filename, and the handler ran it through `filepath.Base` to keep a form value from naming a file
outside the geoip directory — but `filepath.Base("")` is `"."`. The stored choice was then neither a
filename nor "automatic". It only looked harmless because the fallback happens to work: a stat of the
geoip directory itself finds a directory and gets skipped, so the newest database was used anyway.
The empty choice is stored as it came now, and a `.` left behind by an older build reads as the
automatic choice it meant.

**A refused download reported the status and threw away the reason.** `401 Unauthorized` does not
tell an admin whether the key is wrong, the account lacks the edition, or the URL is — and MaxMind
answers a bad licence key with exactly `Invalid license key`, which is the whole diagnosis.

The reason it was dropped was sound: a vendor's rejection page can quote the request back,
credential included. That is worth defending against precisely rather than by discarding the
sentence. Every query value we did not put there ourselves is scrubbed out of the body before it is
shown — an allowlist of `edition_id` and `suffix`, not a list of credential-looking parameter names,
because a custom source may call its key anything. An HTML page is dropped whole: it is noise, and it
is where a key is most likely to sit inside markup a query-value scrub would not catch. The existing
test that no error may carry the key still passes, and now covers a body we do show.

## Changed

**The form asks only for what the chosen source needs**, which is how the panel this was modelled on
does it and is the difference somebody hit while setting MaxMind up:

| Source | Edition | Credential | URL |
| --- | --- | --- | --- |
| MaxMind GeoLite2 | optional | licence key | — |
| DB-IP City Lite | — | — | — |
| IPinfo Lite | optional | token | — |
| Custom URL | — | — | required |

DB-IP took no account and published one database, yet was shown a greyed-out edition box and a key
box: two controls that could only mislead.

The rest of the section followed from the same reading:

- **Every control is labelled.** Three boxes in a row with no labels left the middle one — the
  edition — reading as a required field nobody could name.
- **The sources say what they are**: "city-level, free licence key required", "city-level, **no
  account needed**", "country + ASN only". The second line is the answer to "I do not want to deal
  with a key", and it was not on screen.
- **The edition's placeholder is its default**, with "blank means GeoLite2-City" underneath, so
  leaving it empty and typing it are visibly the same act.
- **The installed databases are listed once.** They were in the picker and then repeated as a bullet
  list of the same filenames below it. What each one is now labels the option that selects it, and
  `city` reads as "city-level" rather than as a raw field value.
- The download result is an alert rather than a line of coloured small text, the two footnotes are
  one, and MaxMind's 30-day licence term is mentioned only when MaxMind is the source.

## Verification

Go and web suites (310 web tests, 8 new), vet, gofmt, both builds, and `scripts/e2e_check.py`.

The new web tests pin the table above — which controls each source shows, that a stored `.` reads as
automatic, and how an option is labelled. The label builder is a plain function so it can be tested
without antd's virtual list, which jsdom never lays out.
