# v0.4.32 — the panels stop pretending a phone is a desk

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema changes and nothing to run by hand. Rolling back
to v0.4.31 is clean.

**Nothing here changes what a page says, only how it lays itself out when there is no room.** Every
change is in the SPA; the server is untouched.

**Three tables behave differently on a narrow screen.** The audit log and the SSO claim list render
as cards below their breakpoint rather than as tables; the SSO group-rules table scrolls sideways
instead of compressing. The rows, the fields and the order they are read in are the same.

## Fixed

**The audit log was unreadable on a phone.** Six columns with fixed widths, and nothing telling the
table what to do when the screen is narrower than their sum. antd does not refuse that — it squeezes
the columns until a Chinese sentence wraps one character per line, so the detail column arrived as a
vertical string of single glyphs and the rest of the row was a column of them beside it.

Below `lg` the same rows are cards now: one row per card, each field on its own line at full width,
in the order the table had them, and the card itself opens the full record — there is no room for a
48px button column, and a tap target the size of the row is the one a thumb hits. Tapping the IP
still filters the log rather than also opening the dialog over the result.

`lg` rather than the `md` this codebase usually switches on, because the audit page sits inside the
manage layout, which keeps its sidebar from `md` up: a portrait tablet has about 600px of content
for a table that wants 1040, and cards read better there than a table scrolled sideways with the
detail column off the edge. Above `lg` the table is unchanged, except that it now scrolls rather
than squeezes.

The five filters move out of the card header, which on a phone is barely wider than one of them.
All but the search box fold behind a button that carries a dot whenever one of them is set — a
folded-away filter must not silently explain an empty page.

**The report card's header crushed its own title.** Title on the left, actions on the right, one
flex row: on a phone the buttons won and antd shrank the title until a single character of it was
left, so the card read "6" where it should have read "688565重组综合决策" — and the row still ran
past the edge of the screen.

Below 700px of reading column the header wraps: the title takes its own line and is allowed to use
it, the buttons take the line below. A container query rather than a viewport one, so it follows the
reading column — the app shell's own chrome comes out of that width first. Both readers share the
card, so both are fixed.

**The SSO page ran off the right edge in two places.** The green tag beside "fetch and validate"
holds what the fetch found: the IdP's entity ID, which is a URL, and antd keeps a tag on one line.
The row wraps now, and the tag breaks the URL when it is the part that does not fit.

The claim list under the attribute mapping was worse. Every name in it is a 70-character URN and
every value beside it is another URN, an address or a GUID — none of them with a space to break at.
Two columns of that on a phone left the name column about two characters wide while the value column
pushed the table clear off the card. Below `md` the pair stacks: the name, then its value under it,
each with the full width. On a wider screen the table stays, but its value column may now break
mid-token, which is what stopped one long GUID from setting the table's minimum width.

**The SSO group-rules table had nothing to say about a narrow screen.** Eight columns of editable
controls want about 1100px; at 390 it compressed every select and input to the width of its own
border. It scrolls sideways now, which at least leaves each control usable.

## Verification

Go build, vet and gofmt; the Go suite; web typecheck, 371 web tests and the SPA build.

Two of the new web tests pin the audit page and the SSO page to a stated breakpoint. jsdom's
`matchMedia` matches nothing, so both had been rendering their phone layout under test without
saying so; each now covers the wide layout deliberately and has a second test for the narrow one.

jsdom asserts nothing about layout, so each screen was also rendered in a real browser at 360, 390,
820 and 1280 px against the actual components and checked for horizontal overflow — which is the
defect all three of these were.
