# v0.4.66 — high-input workflows fit the screen

From v0.4.65, pull and restart. No database schema change or migration is required.

## Run analysis

- The desktop dialog is now a wide, two-column work surface: workflow inputs use the larger left
  side while scheduling, priority, retries, notifications, and queue status stay in a stable right
  rail.
- Short inputs share a two-column grid. Paragraph, JSON, and file inputs keep the full row, and an
  expanded long form scrolls inside the dialog instead of growing beyond the viewport.
- Each Dify workflow can enable **Collapse optional inputs by default**. Required inputs always stay
  visible, the optional-field count opens the rest on demand, and values survive re-collapsing.
- Narrow screens retain the existing one-column flow.

## Workflow management

- The target list shows a bounded three-input preview followed by a clickable `+N` chip. The full,
  wrapping input list opens in a popover, so a workflow with many inputs no longer widens the page.
- The optional-input preference is stored in the target's existing configuration JSON and is
  preserved by edits and input refreshes.

## Validation

Backend tests, frontend type checking, all 732 frontend tests, the production frontend build, and
desktop/mobile browser checks pass.
