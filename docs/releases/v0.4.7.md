# v0.4.7 — the public URL moves to General

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema change, and the stored
setting is untouched, so nothing needs re-entering.

## Changed

The Public URL setting moved from Manage → Email to Manage → General, under a
new "Address" heading.

It sat with email because password-reset links were the first thing that
needed an origin a forged Host header cannot poison. Six more features have
come to depend on it since — the SAML entity id and ACS URL, the OIDC redirect
URL, the WebAuthn relying-party id, registration confirmation links and the
captcha host check — so email is one consumer of seven, and the setting
describes the deployment rather than any of them.

The tell was in the code: enabling SSO failed with "set the Public URL
(Manage → Email)". A setting whose location has to be explained inside another
feature's error message is filed in the wrong place. Both cross-references now
point at General.

The `public_url` key is unchanged, so every reader keeps working and the value
survives the upgrade. Tests cover that, and that an unrelated settings save
cannot wipe it — the field is a pointer, so an omitted key means "leave alone"
rather than "clear", the rule the SMTP password already follows.

## Added

Validation the setting never had: an origin only, rejected on both sides. A
path here would be concatenated into every reset link and redirect URL, and an
IdP handed a redirect_uri it was not registered with rejects the login — a
failure that surfaces at someone else's sign-in, not at the form that caused it.
