# v0.4.36 — a weekly window is a set of days, not one day at a time

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema changes and nothing to run by hand.

**One thing looks different without you configuring it.** The run form's preset-window picker now
shows the window's *name* where it used to show the name followed by the whole timetable. The rule
did not go anywhere: it sits under every option in the open drop-down, and in full behind the info
button beside the picker. If you want it printed inline again, 管理 → 运行默认 → 显示完整时段规则.

Rolling back to v0.4.35 is clean. The new setting is a `meta` scalar an older build ignores, and
every preset this release writes uses the same `intervals` shape v0.4.35 wrote — a weekly window is
still one interval per occurrence on the wire and in the table. Nothing about how a run is scheduled
changed: the resolver, the overrun sweep and the snapshots riding on in-flight jobs are byte for
byte what they were.

**Seven new UI strings**, in all three locales.

## Changed

**A weekly window is configured by weekday.** A weekly preset stores one interval per occurrence, so
"周一、周三、周五 09:00–12:00" — one thing you decided — had to be entered three times, each as a
start weekday, a start time, a stop weekday and a stop time, with nothing on screen saying the three
belonged together. The editor now works in rows: **a set of weekdays sharing one time range**, with
`加一段` for a week that has more than one range. Reading a stored preset back groups the intervals
into the rows they came from, so an existing window opens as the rule you meant rather than as its
expansion.

**A row that ends before it starts runs past midnight**, and lands on the following weekday — the
form marks it 次日. This is not cosmetic. Left on the same weekday, the resolver's period wrap turns
`22:00–02:00` into a **six-day** window, which is the one place that wrap does not mean what a
reader expects. Equal times are a full 24 hours.

**The run form names the window instead of reciting it.** "DS-低峰价期间 · 每天 避开 09:00–12:00、
14:00–18:00" is longer than the control it sat in, and a control whose job is to say which window is
chosen does not need to say the timetable too. The picker shows the name; each option in the open
drop-down carries its rule underneath in small type, so choosing is never a choice between names
alone; and an info button beside the picker opens the whole rule — recurrence, every sub-window on
its own line, and what happens to a run the window closed on.

**Summaries read the way the windows were configured.** A weekly preset names its days once per
range ("周一/周三 09:00–12:00") instead of once per edge ("周一 09:00–周一 12:00"), and a window
running past midnight is written "22:00–次日 02:00" rather than reading as one that ends before it
starts.

## Added

**`run_show_preset_rule`** — bool, default off, at 管理 → 运行默认. Prints a window's whole rule
after its name in the run form, which is what v0.4.35 did unconditionally. It is deliberately not
one of the run-form *defaults* it sits among: the user cannot override it in the form, it decides
what the form shows. It keeps its own key and its own name on each endpoint —
`run_show_preset_rule` on `/api/admin/batch/config`, `show_preset_rule` on
`/api/admin/batch/presets` — both read off one getter, so the two spellings cannot disagree.

## Fixed

**The add-preset button stood on the list.** `+ 新增预设` sat six pixels under the last window, the
same gap the windows keep between themselves, so it read as another row of the list rather than as
an action on it.

**A Sunday edge displayed as Monday.** Weekday 0 is Sunday and the wire drops it
(`json:"weekday,omitempty"`), so a window whose stop lands on Sunday comes back with no weekday at
all — and the anchor editor's fallback assumed 1. It showed 周一 for a Sunday edge. The value was
never written back, so no stored window was wrong; the form was.

**An unnamed window would have rendered as a blank option.** Now that the picker shows only the
name, a window created through the API without one falls back to the same （未命名） placeholder the
admin list already uses.

## Notes

A window that spans whole days — `周一 09:00 → 周三 18:00` — has no row form, and that preset keeps
the per-edge anchor fields rather than being rewritten into something the rows can say. New presets
only ever produce row-shaped windows.

Taking a **monthly or yearly** preset through 每周 and back is lossy: a window on day 15 comes back
on day 1, and two windows sharing a time range come back as one, because rows are keyed by time
range alone. The old editor round-tripped this by accident — it only ever added fields, never
stripped them. It is left as-is: the form shows the result, the day inputs reading 1 and the window
list shorter, before anything is saved. Changing the kind of rule changes the rule.

Multi-day rows make the ISO-week edge in the overrun sweep easier to reach. Any row set whose
windows cross the Sunday/Monday line straddles the week boundary, so the sweep sees two periods
rather than one. `顺延到下一次` behaves identically either way — it rolls to the same next window —
so only `取消任务` differs, and only for that day pairing. See ADR 0014, which the reasoning behind
all of the above is written into.

## Verification

Go build, vet, gofmt and the full Go suite; `govulncheck` reports 0 reachable findings. Web
typecheck, 433 tests across 68 files, and the SPA build. Twenty-two of those tests are new: the
weekly rows' grouping, expansion and round trip — including Sunday, the Saturday-to-Sunday wrap,
equal times, an empty row and a whole-day span the rows must refuse — the summary wording for both,
the editor showing a stored weekly preset as one row and saving it back unchanged, the picker naming
the window with and without the setting, and the rule behind the info button. The change was also
put through an adversarial review: five findings raised, all five refuted on verification, two of
which are why the Sunday-edge and unnamed-window fixes above are in this release.
