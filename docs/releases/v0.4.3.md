# v0.4.3 — the audit release

An audit for unused code and schema leftovers, plus the two real defects it
turned up. This is the version to upgrade a v0.3.10 production database to.

## Upgrade notes

From v0.3.10 — one step, and everything in the v0.4.1 upgrade note still
applies. Back up first: this release rebuilds the unique index that defines
report identity.

From v0.4.0 or v0.4.1 — no longer supported. The three copy-then-drop
adoption steps that made it work are gone (see below). SSO shipped in v0.4.1
and no deployment ever ran it, so nothing real is stranded; a v0.4.1 database
with SSO configured must be recreated rather than upgraded.

Schema: no change. Nothing added, nothing dropped.

## Fixed

One username namespace. userPrincipal folds case, because a read principal
has to be stable, and the account namespace did not: users.username is a
plain TEXT PRIMARY KEY, BINARY on SQLite and case-sensitive on Postgres.
`Alice` and `alice` were two accounts sharing the one principal `u:alice` —
each read the reports granted to the other, and deleting either wiped both
their viewer rows. The SSO path was worse: sanitizeSSOUsername already
folded, so JIT met a case-sensitive collision guard and provisioned a second
account for a name a local password account already held. Names are folded
at every creation path and the guards compare through LOWER(); login stays an
exact primary-key hit. A database that already holds such a pair is named at
startup, since folding new writes cannot retrofit an old collision.

Deleting an account takes its credentials with it. DeleteUser swept the two
grant tables and stopped. Five more are keyed by the username, and the name
is re-registerable, so each miss was an inheritance: a passkey (the previous
holder could sign in AS the new account, with no expiry), chat threads,
recurring tasks that keep firing and keep spending quota, urgent-run tickets,
and pending reset/verify links. batch_jobs is deliberately left — run history
must outlive the person and carries no grant.

The reading-settings popover follows its button when wide reading is toggled.

## Added

An admin UI for the SSO group rules. The engine shipped in v0.4.1 with a
store, two endpoints, a package and tests, and nothing ever called them — so
the rule list was always empty and every federated login fell through to the
provider defaults. The rules decide role AND organizational unit, and the OU
carries report visibility, the run allow-list and the daily quota, so this is
where a federated user's real permissions are set. ssorules.Shadowed is now
surfaced too: a rule that can never fire reads to an admin like a permission
they granted.

## Removed

Three migrations that could not fire — the keyring move, the group-rules move
and the auth_requests rename all guarded by a tableExists that is always
false on a supported database.

Fifteen unreachable Go functions: some obsolete (StartItem, an unguarded twin
of the atomic MarkItemRunning admission; the ADR 0022 read-side subtype
narrowing that ADR 0024 superseded), some merely test-only and moved to a
_test.go file. IdentitiesOf and UnlinkIdentity were KEPT with a comment: they
are an admin action the portal still owes, and hiding them would make a
missing feature look closed.

52 locale keys with no reference left, and two unused types.

golang.org/x/image past two TIFF advisories unreachable from this codebase.

## Verification

Go and web suites, vet, staticcheck, govulncheck, gofmt, both builds, and the
Postgres integration tests — which earned their keep: the PG case caught that
the new username guard folded case but did not trim. scripts/e2e_check.py at
77/77 against a real running portal.
