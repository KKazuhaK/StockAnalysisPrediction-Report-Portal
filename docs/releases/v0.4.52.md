# v0.4.52 — a price on the reading page, and the crash that was already there

## Upgrade notes

From v0.4.3 or later — pull and restart. **No schema change and no migration**: this release
stores nothing. The quote lives in memory for between thirty seconds and five minutes and is
then thrown away, so rolling back to v0.4.51 removes the panel and leaves no trace behind it.

The portal now makes outbound requests to `web.ifzq.gtimg.cn`, `qt.gtimg.cn`,
`hq.sinajs.cn` and `money.finance.sina.com.cn` when somebody opens a stock page. The first two
of those were already reached at ingest for company names. On a deployment that cannot reach
them the panel says so and the report below it renders exactly as before.

## Fixed

**A six-byte symbol could take the process down.** `marketPrefix` validated the length of a
stock code and its first byte, and nothing else; the ingest handler only trimmed whitespace,
which does not strip a NUL. So a code such as `6\x00abc` was accepted, interpolated into a
vendor URL, and handed to `http.NewRequest` — which refuses a control character in a URL and
returns a nil request. The next line set a header on it. That ran inside the bare goroutine in
`Names.Resolve`, and the only `recover` in the tree is in the batch runner, so the panic ended
the binary rather than the request. Reproduced directly before fixing, and the test fails again
if the digit check is removed.

**A blocked deployment looked like a healthy one.** `httpGetGBK` checked no status code, so a
403 interstitial was GBK-decoded, failed the name parse, and returned the empty string — the
same value a network error returns. Two sources with no way to tell "this one refused us" from
"this one had nothing" is one source with extra steps. Both name and quote fetches now go
through `vendorGet`, which refuses a non-2xx, bounds every body with `io.LimitReader`, carries
a context deadline, and logs at most one line per host per minute.

That status check has a second effect worth knowing about: `FetchAShareNames` reads a zero-row
page as "past the last page" and stops. Because a 403 used to be parsed rather than retried, a
single refused page silently truncated the whole company-name table to whatever had arrived.

## New

**Live quotes and a daily candlestick chart on the stock page.** Last price, change, the
vendor's percentage, open, previous close, high, low, volume and turnover, with the vendor's
own timestamp and which source answered — above the report, because it describes the stock
rather than the report you are reading. Under it, a hand-rolled SVG candlestick chart with a
volume panel, over one month, three months, six months or a year, navigable by keyboard.

Tencent's `fqkline` endpoint is the primary source because one call returns the daily series,
the live snapshot **and** the exchange session state together, keyed by the `sh`/`sz` prefix
the name fetch already computes — the three cannot disagree about which instant they describe.
Sina is the fallback. eastmoney, the vendor the batch name fetch already uses, was measured and
rejected: its history endpoint returned an empty body and it needs a numeric id this portal
does not have.

Four decisions are worth stating because they are hard to revisit later:

- **Every price is an integer number of 分.** The schema declares 222 `TEXT`, 61 `INTEGER` and
  24 `BIGINT` columns and not one `REAL`, and `REAL` is a double on SQLite and a 4-byte float
  on Postgres.
- **The percentage is the vendor's, rendered verbatim.** Recomputing it from last and previous
  close prints a fake double-digit crash on every ex-rights day. The one exception is the Sina
  fallback, which publishes neither number — ADR 0028 says so at the point where the promise is
  made, rather than leaving a reader to find out.
- **The chart is 不复权.** Front-adjusted history is re-based by every dividend, so a bar
  cached in July is a different number in December.
- **Nothing polls.** There is no interval scheduler in this codebase, and five thousand codes
  at one request a minute is roughly 7.2 million writes a day against a database held at one
  connection. Fetch-on-read with a TTL taken from the vendor's own session field, plus a
  single-flight, gives the same freshness and adds no background loop.

**The Beijing exchange gets a price and no chart, on purpose.** Tencent returns an empty daily
array for `bj830799`; Sina's series for the same code stops at 2025-04-29 while the live price
is 34.28. Sixteen-month-old data that looks like data is worse than none, so the panel says
there is no history for this market instead of drawing an empty frame that reads as a flat line.

**The drift gate is the part that matters.** These are positional index reads over bodies with
no schema and no changelog. The realistic failure is a vendor inserting one field, after which
every range check still passes and the portal renders a confident wrong price. What actually
catches that is an arithmetic identity — the vendor's own percentage has to agree with its own
last and previous close — plus an exact code echo at a known index, per-candle ordering, and a
field-count floor. There is deliberately **no** band on the size of the move: A-share limits
are ±5/10/20/30% by board and a first-day listing has none, so any band wide enough to keep a
real limit-up day is too wide to catch anything.

## Also recorded, and deliberately not built

[ADR 0029](../adr/0029-prediction-scoring-deferred.md) writes down the design for scoring
predictions against what actually happened, and states in its first line that no code
implements it. It is worth reading for two findings that reorder that project: `SetTracking`
deletes every tracking row on each re-ingest, so any machine-computed verdict is erased by the
next nightly run; and an empty tracking array is a silent no-op, so a claim that is going wrong
can be dropped without a trace. It also explains, at length, why there is no accuracy
percentage and why there will not be one.

## Verification

Whole `internal/app` suite green, including under `-race`. 60 Go test functions and 28
subtests across the four new test files, 38 web tests across the three new component and
helper files, and two more in the stock page's own test that exist only to fail if the panel
is ever unhooked from the page again.

Every guard in this release was checked by removing it and confirming a test turns red —
including the ones added after two rounds of adversarial review found seventeen assertions
that would have passed with the code they claimed to cover deleted: eleven in the first round
(the Beijing scrub, the `Cache-Control` remaining-TTL claim, the nil-request check that is this
release's own crash fix, and eight more around the cache), two in the web components, and four
more introduced by the first round's own fixes.
