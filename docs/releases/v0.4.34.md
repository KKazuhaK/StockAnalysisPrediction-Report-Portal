# v0.4.34 — the run dialog opens on what you configured

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema changes and nothing to run by hand. Rolling back
to v0.4.33 is clean: the four new defaults stop being read and the run dialog opens the way it did
before, with the two older ones (default mode, pre-checked 队列空闲) still honoured from where they
have always been stored.

**Nothing changes for a portal that sets none of them.** Every new default ships as "no default" —
no workflow pre-selected, no window pre-picked, 0 retries, no pre-ticked email — which is exactly
the empty form the run dialog has always opened with.

**One page moved.** Default mode and "pre-check 队列空闲" are no longer on Manage → 运行/队列; they
are on the new Manage → 运行默认 beside the rest of the run-form defaults. Their stored values are
untouched, so whatever was set is still set — it is just edited one page over, and the run/queue
page links to it.

## Added

**The run form's defaults are their own settings page.** Manage → 运行默认 decides what 运行分析 is
already holding when it opens: which workflow, which of the three time buttons, which preset window,
whether 队列空闲 is pre-checked, how many failure retries, and whether "完成后邮件通知" starts
ticked. Two of those existed already, as a pair of rows wedged between the queue's concurrency
budget and its Slurm priority weights — settings that govern how the queue *behaves*, which these do
not. Nothing here changes the engine; it changes what the dialog is pre-filled with, and the user
can still change any of it before running.

**Every default can be no default.** Each picker carries a 不预设 entry, and choosing it clears the
setting rather than leaving the old one behind — a portal where users run a different workflow every
time is not worse off for the page existing.

**A default workflow.** The 运行分析 picker opens on it instead of empty, which for a portal with
one workflow that everyone runs removes a click from every run. An entry button that names its own
workflow still wins — that is the whole point of pinning one — and a choice the user has already
made is never overwritten.

**A default preset window.** 预设时间 mode arrives with the window already chosen, so a run into the
low-peak period is two clicks rather than three. The batch console gets the same, since it shares the
schedule control.

**A default retry count and a default done-email.** Both are per-run options the operator was
re-setting on every run; they are pre-filled now. The email default only takes effect for a user who
has a verified address on a portal that can send mail — the checkbox is not drawn for anyone else,
and a default must not post a value on behalf of a form field nobody was shown.

## Changed

**Standard-library advisories cleared.** The build moves from Go 1.26.5 to 1.26.6, which is where
seven advisories `govulncheck` finds *reachable* from this code are fixed: `net/url`
(`resolvePath` quadratic complexity), `html/template` (JavaScript regexp context tracking),
`crypto/tls` (post-handshake message flood), `net/http` (`ReadHeaderTimeout` skipped on the
unencrypted HTTP/2 check, and the `x/net/idna` Punycode label check), `encoding/xml` and
`encoding/asn1` (recursion depth guards). All seven are in the standard library, none in this
portal's own code or its dependencies — the reachable paths run through the SAML ACS handler, the
PDF template render, the Dify upload client and the listener itself. Nothing here changes behaviour;
the archives and images for this release are simply built on the fixed toolchain.

## Notes

A default names a row — a workflow, a window — so it can go stale, and both ends of that are
handled. A save naming a workflow or window that does not exist is dropped rather than stored. A
stored default whose row has since been deleted reads back as "no default", instead of leaving a
bare id sitting in the admin's own picker looking live. A window that is merely *switched off* is
deliberately not forgotten: the run form won't offer it, but the admin who switched it off finds
their choice waiting rather than silently cleared — and if the default workflow has been hidden from
运行分析, the settings page still lists it, marked, so it can be kept or cleared rather than
disappearing without explanation.

The defaults ride on the presets response the run dialog already fetches, so an opening dialog makes
no extra request for them.
