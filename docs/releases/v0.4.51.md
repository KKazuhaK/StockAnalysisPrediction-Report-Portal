# v0.4.51 — ten more controls that needed a mouse

## Upgrade notes

From v0.4.50 — pull and restart. No schema changes, no configuration, no API changes.

## Fixed

v0.4.49 made the report cards, the app cards and the icon buttons work without a mouse. Its guard
only knew about those two component types, so it reported success while ten other controls were
still unreachable — including one on the login page and three that are the primary way to navigate.

| Where | What it is | Why it was unreachable |
| --- | --- | --- |
| Login / register / password reset | Get a new captcha image | an `<img>` takes no focus at all |
| Reader | The date timeline | an `<a>` with no `href` is not focusable |
| Review queue | Open the report behind an item | same |
| Compare | Show / hide unchanged sections | same |
| Assistant | Pick a conversation | a `<div>` with `onClick` |
| Assistant | Expand the model's reasoning | a `<span>` with `onClick` |
| Assistant | Retry after a failed load | antd `Typography.Link` with no `href` |
| Audit log | Filter by an address (two places) | same |
| Report history | Pick a revision | antd `List.Item`, which is given `tabIndex=-1` |

The last four are the ones a component library was supposed to have handled. `Typography.Link`
without an `href` renders an anchor that antd *does* make focusable — and Enter still does nothing,
because an anchor's activation behaviour requires an `href`. So a keyboard user could reach it and
press Enter and get silence, which is worse than an obviously dead control. `List.Item` is rendered
with `tabIndex=-1`, so Tab cannot reach it at all — that one was the revision picker in the report
edit history.

The captcha one is the sharpest: it is on the page you have to get through before anything else, and
a challenge you cannot refresh is a login you cannot complete.

All ten are now focusable, announced as controls, and activated by Enter or Space. None of them
gained a label it did not need — an `aria-label` *replaces* the visible name rather than adding to
it, so the nine that already show their own text keep announcing exactly what they read. Only the
captcha image, which has no text, is given a name.

**The guard is what actually changed.** It now checks every plain element carrying an `onClick`, not
just the two component types it knew about — an `<a>` without `href` counts as unreachable, since
that is what makes an anchor focusable. A second rule covers the two antd components above, which the
"components manage their own semantics" exemption had been waving through.

Both antd behaviours are pinned by a test that renders them, rather than asserted in a comment: a
rule about a third-party library rots silently, and this way an antd upgrade that fixes either one
turns a test red so the rule can be removed instead of outliving its reason.

## Also fixed

**A test that could pass for the wrong reason, and one that could fail for none.**

The audit log's "open a row in full" test had a known habit of failing under load and passing on an
idle machine, and the previous fix — waiting until the button is genuinely clickable — was only half
of it. It held the button element from *before* the wait, and a detached node reports no
`pointer-events` at all, so once antd re-rendered the table the wait was satisfied by a node that had
already left the page and the click landed nowhere. Load makes that re-render likelier, which is
exactly where it failed. The element is re-queried now, and "reachable" answers false for a node that
is no longer in the document — verified directly: the old check called a detached node reachable.

Separately, the webhook test asserting that a content-neutral save fires nothing was doing it by
waiting 300ms and seeing nothing arrive. Under load that passes because the event it should have
caught was merely late, which is a guard that quietly stops guarding. It is an ordering assertion
now: a silent save followed by a real one, where the first event received must be the real one.

## Verification

Web typecheck, 82 files / 554 tests, locale parity, and the SPA build. Go build, vet, gofmt and the
full Go suite (unchanged this release, run to confirm it).

Each new rule was confirmed by putting a violation back: the scan names the file, the line and the
component. The
optional label is tested from both sides — an element with its own text keeps that text as its name,
one without gets the label — and an `href`-less anchor is tested to be focusable and Enter-activated,
which it is not on its own.
