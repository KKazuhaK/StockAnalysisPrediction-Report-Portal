# v0.4.51 — six more controls that needed a mouse

## Upgrade notes

From v0.4.50 — pull and restart. No schema changes, no configuration, no API changes.

## Fixed

v0.4.49 made the report cards, the app cards and the icon buttons work without a mouse. Its guard
only knew about those two component types, so it reported success while six other controls were
still unreachable — including one on the login page and three that are the primary way to navigate.

| Where | What it is | Why it was unreachable |
| --- | --- | --- |
| Login / register / password reset | Get a new captcha image | an `<img>` takes no focus at all |
| Reader | The date timeline | an `<a>` with no `href` is not focusable |
| Review queue | Open the report behind an item | same |
| Compare | Show / hide unchanged sections | same |
| Assistant | Pick a conversation | a `<div>` with `onClick` |
| Assistant | Expand the model's reasoning | a `<span>` with `onClick` |

The captcha one is the sharpest: it is on the page you have to get through before anything else, and
a challenge you cannot refresh is a login you cannot complete.

All six are now focusable, announced as controls, and activated by Enter or Space. None of them
gained a label they did not need — an `aria-label` *replaces* the visible name rather than adding to
it, so the five that already show their own text keep announcing exactly what they read. Only the
captcha image, which has no text, is given a name.

**The guard is what actually changed.** It now checks every plain element carrying an `onClick`, not
just the two component types it knew about — an `<a>` without `href` counts as unreachable, since
that is what makes an anchor focusable. That rule is what found these six, and it is why the next one
cannot be added quietly.

## Verification

Web typecheck, 81 files / 547 tests, locale parity, and the SPA build. Go build, vet, gofmt and the
full Go suite (unchanged this release, run to confirm it).

The new rule was confirmed by putting one of the six back: the scan names the file and line. The
optional label is tested from both sides — an element with its own text keeps that text as its name,
one without gets the label — and an `href`-less anchor is tested to be focusable and Enter-activated,
which it is not on its own.
