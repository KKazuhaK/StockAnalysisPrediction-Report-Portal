# v0.4.2 — a smaller schema behind the same behaviour

No new features and no behaviour change. This release makes the v0.4.1
schema smaller and the scoped read faster, and it is the version to
upgrade a v0.3.10 production database to.

## Upgrade notes

From v0.3.10 — everything in the v0.4.1 upgrade note still applies and
still happens in ONE step. Back up the database first; this release
rebuilds the unique index that defines report identity. The three
table moves below are no-ops on a v0.3.x database, which never had
those tables.

From v0.4.0 or v0.4.1 — the three moved tables are copied into `meta`
and then dropped, automatically, on first start. Copy-then-drop, so a
process killed mid-move finds the source table still there next boot.
Nothing to run by hand.

Schema: three tables removed, one renamed, no new columns.

## What changed

SSO went from six tables to three. sso_keyring held one salt and one
wrapped key in a table that could only ever have one row, and now holds
them as two `meta` settings — rotating the portal's secret_key still
re-wraps one value rather than re-encrypting every secret.
sso_group_rules was an ordered list that every write already replaced
whole, and is now one JSON `meta` value that cannot end up
half-applied. sso_auth_requests is now auth_requests: the name stopped
being true when TOTP, WebAuthn and email verification started parking
their pending requests in it.

The scoped read stops scanning every report. The disclosure predicate
used a correlated EXISTS, which makes the ownership test a per-row
probe and forces the planner to scan the whole table; an uncorrelated
`id IN (subquery)` is evaluated once and drives a primary-key search.
Measured at 200k reports: the report list 18.4ms to 11.7ms, the home
feed 24.4ms to 18.1ms, and the gap widens with the report count
because what disappears is proportional to it.

Correction to an earlier claim: a "130x" figure quoted during this work
was not a like-for-like comparison. The numbers above are.

golang.org/x/image bumped past two TIFF-decoder advisories that are not
reachable from this codebase.

## Verification

Go and web suites, vet, staticcheck, govulncheck, both builds, and the
Postgres integration tests. Each table move has a test that puts data
in the old shape and proves it survives. scripts/e2e_check.py at 77/77
on a fresh install and on a real v0.3.10 database upgraded in place.
