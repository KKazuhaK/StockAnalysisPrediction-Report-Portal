# v0.4.27 — the footer sits on one line, not one and a bit

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema changes, nothing to run by hand, and rolling
back to v0.4.26 is clean: this release changes how one line of markup is laid out.

## Fixed

**The site name and the version number in the page footer were drawn at different heights.** The
name and its logo rode about a pixel above the version beside them — enough to read as a crooked
line without it being obvious what was wrong with it.

The name and logo were grouped in an inline-flex box, and that box sat inside the flex row laying
out the footer. An inline-flex box takes its baseline from its first flex item, and the first item
here is the logo — a replaced element whose baseline is its own bottom edge, not a text baseline.
That made the group measure 16.5px tall against the 14px of the items next to it, and centring
boxes of unequal height offsets their contents by half the difference. Measured: the name's line
box began at y=32.00 where the version's began at y=33.25.

The footer is now one plain inline flow — no flex row, no nested flex box. Inline text shares a
baseline by construction whatever else sits on the line, and the logo gets to keep the optical
nudge it already carries (a `vertical-align` a flex parent silently ignored). Centring and wrapping
still come from the footer's own `text-align`, so a narrow screen behaves as it did.

## Verification

Go build, vet and gofmt; the Go suite; web typecheck, 339 web tests and the SPA build.

The defect and the fix were both measured in a browser against the real markup rather than argued
from the stylesheet: the two line boxes now start at the same y, and the logo's centre lands 0.7px
above the text's — its intended optical offset rather than a layout artefact. The test asserts the
arrangement that caused the split (no part of the footer boxed off in its own flex container),
since jsdom has no layout engine and cannot see a baseline.
