# External-user access: OU tenancy, owner-scoped reads, run quotas, account validity

Opens the portal to external (non-company) users without changing anything for internal
ones. Every new rule fires only for a "restricted" organizational unit, so internal staff
and admins are unaffected and the batch money-path is byte-for-byte unchanged.

- Organizational units: user_groups becomes an OU tree (parent_id) whose settings resolve
root-to-leaf. Marking an OU "external/restricted" is sticky down its whole subtree.
- Reports are stamped with the OU that generated them, and a restricted member reads only
its own OU's reports plus today's internal ones. Enforced in SQL on every read path,
including by-id deep links, exports and the omnibox.
- If a report already exists for today, requesting it returns that report instead of
running again — and costs no quota.
- Per-OU daily run quota, and a per-OU allow-list of which workflows may run and where they
appear, both enforced server-side.
- Accounts can carry a validity date; expiry ends an active session immediately.
- SSO is not included; it is the next initiative.

Database: additive only — a new group_targets table plus reports.owner_group,
users.expires_at and three user_groups columns, all applied automatically on first start.
No backfill and no manual migration.

Upgrade note (0.y boundary): a v0.3.x database must be running the last v0.3.x release
before upgrading to v0.4.x; it cannot skip the end of the previous line.
