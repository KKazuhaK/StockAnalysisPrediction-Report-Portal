# v0.4.48 — the 5日 button works, and the panel stops promising windows nothing serves

## Upgrade notes

From v0.4.47 — pull and restart. No schema change, no migration, no new setting, and no new vendor
host: the five-day window comes from a second endpoint on `web.ifzq.gtimg.cn`, which this portal has
been calling since v0.4.45.

Rolling back to v0.4.47 restores the old behaviour, which is that 5日 draws nothing.

## Fixed

**The 5日 button did nothing, for everybody, in every market.** Not a configuration problem — a gap
in the shipped build. Only Yahoo declared the five-day window, and Yahoo ships switched off, so with
the sources an unconfigured portal actually runs the range resolved like this:

```
601899  5日   intraday5d -> snapshot     no chart
00700   5日   intraday5d -> snapshot     no chart
AAPL    5日   intraday5d -> snapshot     no chart
```

Tencent has a second endpoint that answers the same minute rows for **five sessions** —
`day/query`, on the host the one-session endpoint already uses. Measured: Shanghai and Shenzhen
answer 5 × 267 rows, Hong Kong 5 × 332. Those three markets now serve 5日 out of the box.

The rows are rolled into **five-minute buckets**, which is the resolution Yahoo answers the same
label with (331 points for a Shanghai week). Without that, 5日 would mean one-minute detail from one
vendor and five-minute from another under the same button. Every number in a bucket is observed —
open is its first minute's price, close its last, high and low the extremes actually printed, volume
the sum of the minutes — and a bucket holding one minute is that minute.

**Two markets are still out, for two different measured reasons.** `day/query` answers `usAAPL` with
`{"code":-1,"msg":"param error"}` — it does not serve the market. It answers `bj830799` with five
*full* sessions dated **April 2025**: the suspended stock every Beijing fixture here is captured
from, so what is measured is "no series for this code", not "none for the market". Declaring Beijing
on that evidence would draw a year-old week under a 5日 label.

**管理 → 行情源 advertised a window nothing served.** The capability column unioned the two intraday
intervals under one 分时 heading, so Tencent — which declared only the one-session window — was
printed as covering both, and an operator read "5日 works in these three markets" while every 5日
request degraded. The two windows are separate rows now. The test that is supposed to catch exactly
this over-claim did not, because it accepted *either* interval as proof of the merged column; it is
one interval per column now, and a stub whose two windows differ exercises it, since no shipped
source's two windows differ today.

**"该市场暂无历史行情数据" was the wrong sentence, and wrong in the expensive direction.** It was
shown for two different situations: a market whose daily series genuinely is not worth drawing
(Beijing; the US on the shipped sources), and a *window* no enabled source declares. The second is a
configuration fact — the market has the data — so that message is what an operator reads **after**
switching on a source for exactly that window, and it does not change when they do. There is a third
reason code now, and it says where the switch is.

**The 首页卡片显示行情 switch was drawn as a full-width blue bar.** A column flex container stretches
its children, so the switch spanned the card and stopped reading as a control at all — its off state
looked like a progress track that never filled.

**The Yahoo notice set the height of the whole table.** Three sentences of licensing notice under a
360px cap inside the source column wrapped to five lines and pushed its row to about two hundred
pixels. The text is unchanged and still shown by default — it is the one thing on that panel that is
not a status, and hiding it behind a tooltip would mean an operator who never hovers decides without
it. It is now an alert at the card's width, above the table, named per vendor.

**The chart's 元 printed through the top price label.** Both are anchored to the right edge of the
price gutter, so they share an x and can only be separated vertically — and at a 16px top padding
they were not: the gridline label's ascender reached about where the currency's baseline had to sit.

**An undeclared interval would have been drawn as daily candles.** Found while writing the test for
the endpoint routing above: once both intraday windows were wired, the `iv.intraday()` guard in front
of the fall-through became dead code, so any interval this build has no endpoint for went quietly to
the daily fetcher — a series of *days* under whatever label the reader picked, with no error
anywhere. The switch is exhaustive now and its default is a refusal.

**Six Traditional Chinese strings said "dialog box" where they meant "time window".** `窗口` converts
to `視窗` under s2twp, which is right for an application and wrong for a span of time — the same
class of error as `代码 → 程式碼`, which this generator already had a rule for. It has a rule for this
one now, and the six existing strings (SAML assertion validity, the preset overrun hint, and four on
the login-throttle page) are corrected.

## Verification

Go build, vet, gofmt and the whole `internal/app` suite including under `-race`. Web typecheck, the
full vitest suite, locale parity across all three bundles and the SPA build. No new dependency in
`go.mod` or `web/package.json`, and no new vendor host.

Every parser assertion is against a body captured from the live feed on 2026-09-07 and committed
beside the test, never a hand-built one. Each fix was mutation-verified — the fix reverted, a named
test watched to fail, then restored. **Two of eleven mutations survived** and both are now covered:
the endpoint routing, which needed an assertion on the URL each interval actually reaches rather than
on the capability alone; and the panel's merged column, which no shipped source can demonstrate
because every one of them declares its two intraday windows for the same markets.

Six existing tests changed their expectations. Every one of them asserted the limitation this release
removes — that Tencent cannot serve a five-day window — which is what a behaviour change looks like
from a suite that was actually testing something.

## Known, and not fixed here

A deployment running Yahoo has been seen to refuse a US chart with
`yahoo sent no currency, or not the one this market quotes`. It could not be reproduced: the captured
fixture carries `"currency":"USD"`, and `query1`/`query2.finance.yahoo.com` answer **429** from the
environment this was built in. A parser here is written against a committed measurement and not
against a guess, so the currency check is unchanged pending a capture of the failing body.
