# v0.4.15 — the audit log actually covers what it claimed to

## Upgrade notes

From v0.4.3 or later — pull and restart. One additive schema change applied
automatically: `audit_log.ip`, plus an index on `(action, at)`. Existing rows
read as having no source address, which is what they have.

Timestamps written from now on are UTC. Rows written before this upgrade are the
server's local clock and are **left alone**: converting them means inventing the
UTC offset in effect when each was written, and nobody wrote it down. The console
marks them and says so.

To show where an address is, put a MaxMind-format `.mmdb` in `<data>/geoip/`.
Nothing is downloaded and nothing is required — with no database, the log shows
the bare address.

## Fixed

**Two declared actions were written by nothing.** `group.change` and
`policy.change` existed as constants since the log shipped and no code emitted
them. That is worse than a missing constant: the console builds its filter from
the actions present in the data, so both rendered as options that could only
return nothing — which reads as "this never happens", not as "this is not
recorded". A test now walks the declarations and fails if any lacks an emitter.

**The machine API served report bodies without recording a read.**
`GET /api/v1/reports/{id}` and `/reports?with_body=1` bypassed the log. Not a
hypothetical door: the app bridge mints a `query` token for any non-restricted
signed-in user, so every downloadable app read reports through it and every one
of those reads was invisible. The table's own header says who-read-this is the
one question the portal can answer with evidence; for apps and for Dify it could
not.

## Added

**Sign-ins, and refusals.** Every sign-in by all four methods, with which one in
the detail. Every *failed* sign-in with its reason — wrong password, wrong code,
rejected passkey, disabled, expired, refused by policy, and each way SSO can fail
to resolve an account. Lockouts, sign-outs, password changes and resets, second
factors added and removed, identity bindings made and revoked. A log that
records only successes answers half the question, and the failures were the
missing half.

**Runs.** Submitted, cancelled, retried, reprioritized, rescheduled, deleted. The
human decision, never the machine outcome: `batch_items` already stores every
row's status and the console serves it, so a row per item would double the table
to duplicate a record that exists. The scheduler ticks 4,300 times a day and
writes nothing.

**Reports.** Ingest records whether it created or *overwrote* — the identity key
upserts, so "this report changed and nobody knows when" was unanswerable.
Deletion records only when something was removed.

**Administrative operations.** Accounts, OUs, the OU run allow-list with both
sides, API tokens, apps, webhooks, workflow targets, and the four configuration
surfaces.

What a row carries was chosen as carefully as whether to write one. Configuration
saves record field *names*, not values — those payloads are pointer-per-field so
that omitted and cleared differ, which makes the non-nil set exactly what the
admin touched, and one of the values is an SMTP password. Tokens record name,
scope and expiry, never the token; webhooks the URL and events, never the
secret; targets the address on both sides and whether the key rotated, never the
key. A credential in an audit row is a credential in every backup of it.

**The source address, as a column.** Without it, "someone guessed alice's
password" is answerable and "the same host tried nine other accounts" is not —
and only the second turns a pile of failures into one incident. It could not live
in the detail blob: that is reachable only through an unindexed substring match
that would also hit a target id containing the same bytes, and an address has to
be an equality dimension. It shows under the actor, because on a failed sign-in
it is the only identity there is, and clicking it filters.

**Where the address is, resolved offline.** A local `.mmdb`, memory-mapped, read
directly. No address is sent anywhere to be geolocated — these are the portal's
own visitors, including the ones who failed to sign in, and handing that list to
a third party is the thing this feature must not do.

One reader handles both free schemas, which collide on the same key: MaxMind
nests `country` as an object, ipinfo Lite makes it the country's *name* as a
string. A fixed struct reads nothing from whichever it was not written for, and
that looks exactly like "this address is not in the database".

The place is resolved when the log is **read**, never stored beside the row.
Databases improve and addresses change hands, so a stored region is a snapshot of
what one build once thought, presented later as fact. The active file is the
newest `.mmdb` in the directory, reopened when it changes on disk — by size as
well as mtime, because a file replaced within the same second changes size far
more reliably than a whole-second stamp.

## Changed

**Timestamps are UTC, read in the panel timezone.** Instants are UTC everywhere
else in the portal; this table was the host's local clock, so lining a row up
against a Dify run — the sandbox is UTC — meant knowing the server's timezone,
which nothing recorded. Shown in the panel timezone, with the reader's own
underneath only when the two differ.

Retention now matches each row against a cutoff in its **own** format rather than
relying on the two happening to sort compatibly. They do, at day granularity,
which is fine right up until somebody sets retention to one day.

**Every manage-menu item has its own icon.** 单点登录 and 登录保护 were the same
shield, one above the other — the two pages people confuse most. 类型管理 and 应用
were a grid and the same grid with a plus, which at 14px is one icon.

## Verification

Go and web suites (302 web tests), vet, gofmt, both builds, and
`scripts/e2e_check.py` at 76/76 — with the log filling itself along the way with
**twelve distinct actions** that the script never asks for: sign-ins, refusals,
OU creates and changes, ingests, grants, a password change, a second-factor
change, a token. It was two before.
