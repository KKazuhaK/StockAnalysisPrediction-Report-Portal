# v0.4.42 — reports you write yourself

## Upgrade notes

From v0.4.41 — pull and restart. No schema changes: hand-written reports are ordinary rows of the
table you already have. One row is added to the report-version registry on the first boot, named
`manual` and labelled 人工, granted to nobody — so nothing changes for any reader until you decide
it should.

**One API contract changes.** `POST /api/v1/reports` now answers **400** to an ingest naming the
`manual` version. No workflow sends it today — the name is new — but if you have adopted it for
something of your own, rename that before upgrading. The refusal is the point: it is what stops a
workflow overwriting something a person wrote.

Rolling back to v0.4.41 is clean and lossless. Hand-written reports stay on disk and stay readable;
the older build has no editor, so they simply cannot be changed, and the ingest path can reach them
again — which is the hazard worth knowing about if you roll back with hand-written reports live.

## Added

**You can write a report by hand.** 写报告 in the header opens an editor: Markdown in, previewed
through the same renderer the reading page uses — so tables, formulas, mermaid diagrams and charts
look in the preview exactly as they will when published. A `.md` file can be imported into the body
rather than retyped. Everything a generated report gets, a hand-written one gets: the exports, the
comparison, the search, the timeline, the reading settings.

This is the answer to the case that has had no answer: the workflow missed a report, or got one
wrong, and the person who knows better had no way to publish it.

**A hand-written report can never be overwritten by a workflow, and that is a mechanism rather than
a promise.** It lands in its own version, and the version is part of a report's identity, so a
workflow re-running the same analysis writes its own row and cannot reach yours. An ingest that
names the hand-written version outright is refused. Without that refusal the guarantee would rest on
no workflow ever happening to send that name — and the failure would be silent, because overwriting
reports success.

**Editing a generated report does not change it.** Open one, press 编辑, and you are writing a
*hand-written form of it*: the original keeps saying what the run said, and the two appear side by
side in the report's version switcher. That matters beyond tidiness — the comparison, the diff and
the tracking review all read a generated report as the record of what a particular run produced, and
a report that has been quietly edited makes all three lie.

It also means writing a report from scratch and correcting a generated one are the same act, and the
editor says which one is happening before you start typing rather than after you save.

**A new permission, and a role that holds only it.** 编辑员 may write, edit and delete hand-written
reports, and nothing else — no admin console, no workflow runs. Administrators have it too.

Running a workflow and publishing a report are deliberately separate authorities. A run spends
quota and produces a machine's record of what the workflow said; a hand-written report puts a
person's words out under the portal's name. In practice the analyst who writes the commentary is
often not the person trusted to spend the run budget, and one permission for both makes that
impossible to express.

**Each hand-written report says who it is for.** The editor has the same audience picker the
announcements console has — 所有人, or chosen groups and accounts.

For external readers this is one of two gates and neither is redundant. **Report versions** decides
whether an account may read hand-written reports at all; the **recipients** on the report decide
which ones. Grant the 人工 version to a client and they see the hand-written reports addressed to
them, and no others. Internal accounts are not scoped and never were, so none of this applies to
them.

A report addressed to nobody is refused rather than saved, because unlike an announcement — whose
audience can be emptied later by deleting a group — that state is only reachable by choosing it.

**Hand-written reports can be deleted, from the browser, by the person who may write them.** Only
hand-written ones. Deleting the record of a run is a storage decision and keeps its own console and
its own retention policy.

## Changed

**The audit log distinguishes writing from generating.** `report.create` and `report.edit` are their
own actions alongside `report.ingest`, because "a person wrote this" and "a workflow produced this"
is the first thing somebody reading the log needs told apart. Both record what the report is, who it
was addressed to, and — for one written from an existing report — which report it started from.

**A refusal can now carry more than a reason.** Saving a report onto an identity that already exists
answers with the id of the report it collided with, and the editor offers to open it, because an
author who hits this is almost always writing the report that already exists rather than a different
one that needs a different title.

**The audience picker is one picker.** Announcements and reports address the same people through the
same encoding, and the server now validates both through one function. It is the input to a
disclosure decision, and a second copy of it is a second thing that has to stay right.

## Verification

Web typecheck, 515 tests across 75 files, locale parity, and the SPA build. Go build, vet, gofmt and
the full Go suite.

The new coverage is at the seam between hand-written and generated, which is where this feature can
go wrong invisibly: that a workflow re-running the same analysis lands on its own row and leaves the
hand-written body untouched; that an ingest naming the reserved version is refused and writes
nothing on its way to the refusal; that editing a generated report leaves it byte-identical and
produces a second row the switcher shows beside it; that retitling a hand-written report moves the
row instead of leaving an orphan behind; that a save computed against a stale copy changes nothing,
and that two saves within one second are distinguishable at all — the concurrency token is the write
timestamp, so its precision is load-bearing rather than incidental; that both visibility gates are
required and that holding one without the other reads nothing; that moving a report to another date
carries its recipients with it; that a collision names what it collided with; and that the store
refuses to modify a generated report even when asked directly, not only when asked through the
handler.

On the browser side: which of the three things pressing 编辑 becomes, since the author cannot tell
them apart and the wrong answer only surfaces as a save that fails — including that a report already
hand-written is edited in place rather than seeded into a copy that collides with itself.

The refusals were confirmed by removing them and watching the tests fail, rather than by observing
that they pass.
