# v0.4.25 — things that were painted on top of each other, or off the screen

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema changes, nothing to run by hand, and rolling
back to v0.4.24 is clean: everything here is presentation and one `ORDER BY`, nothing writes data.

**The queue's inputs preview and its hover now show a bounded summary, not the raw inputs.** A long
value is cut at 80 characters and a long list ends with a "+N" count. Nothing is lost — the queue
search still matches the full text, and the run's detail modal still shows exactly what was
submitted — but if you were reading a whole prompt out of the hover, that now lives one click away.

**The audit log's ordering changes for installations that predate v0.4.15.** Rows written before the
timestamp format switched to UTC now sort below every row written after it, instead of interleaving
by string. No row is edited, added or dropped; only the order they come back in.

## Fixed

**A report table's sticky first column showed the columns scrolling underneath it.** On a phone the
first column stays put while the rest of the table scrolls sideways, and on every second row the
text sliding past was legible straight through the label — two strings drawn on top of each other,
in exactly the cell that exists to stay readable.

A sticky cell has to paint fully opaque, and the zebra stripe handed it a translucent one:
`colorFillQuaternary` is `rgba(255,255,255,0.04)` in dark and `rgba(0,0,0,0.02)` in light — a tint
designed to be layered over whatever is behind it, which for a normal row is the table and for a
sticky one is whatever happens to scroll past. Odd rows were fine because they already used the
opaque container colour, which is why the damage in the report lands on rows 2, 4 and 6 and not on
1, 3 and 5.

Both sticky cells now layer their tint over an opaque background instead of using the token bare.
The header row gets the same treatment even though its token is opaque today, so the cell does not
turn see-through the day that changes.

**A run's hover in the queue could fill the screen and then flicker.** The tooltip carried the run's
inputs in full, and an agent run carries its entire prompt in `query` — a few thousand characters.
Past a certain height the overlay gets repositioned until it sits under the pointer, which fires
`mouseleave`, which hides it, which fires `mouseenter`: the flicker was the tooltip toggling its own
trigger, and the text was unreadable at both ends anyway.

The preview is now clamped on two levels, because one cap cannot do both jobs. Each value is clamped
on its own first, so a runaway `query` can no longer push `symbol=301539` out of view — the entry
people actually look for used to be the one truncation ate. Then the list as a whole is capped by
count and by length, with the remainder reported as a trailing "+N" instead of silently dropped.
Entries render one per line, so the hover reads as a list rather than a wrapped run-on, and the
overlay itself is bounded (360×320, with its own scroll) as a backstop that does not depend on the
content estimate holding. The error column, which could produce the same viewport-tall overlay out
of a raw provider error, is bounded the same way.

**The confirm-identity dialog drew a generic padlock for every SSO provider.** The login page draws
the icon an admin configured, so the same provider looked like two different things depending on
which screen asked for it. The step-up policy now carries the provider's configured icon and the
dialog draws it.

**The audit log could show an older entry above a newer one.** Timestamps changed format once — local
wall-clock with no zone, then UTC — and ordering by string alone cannot span that change: on a UTC+8
server an evening legacy row sorts above a strictly newer UTC row purely because its calendar date
has already rolled over. The format switched once and never switched back, so every legacy row
predates every UTC row, and that fact is now the ordering: UTC rows newest-first, then legacy rows
newest-first. Deterministic in any server timezone, which the old comparison was not — its test
passed or failed depending on the time of day it ran.

## Verification

Go build, vet and gofmt; the Go suite; web typecheck, 337 web tests and the SPA build.

Both UI fixes were verified in a browser against the real theme tokens rather than reasoned about.
The table was rebuilt at 375px inside the app's cssVar scope: reinstating the old rule reproduces
the reported overlap on exactly the even rows, and the new rule paints them solid with the stripe
intact. The queue preview was exercised with the reported case — a 1500-character prompt beside a
dozen parameters — where the hover now measures 276px of content in a 720px viewport, lists eight
entries and closes with the "+5 more" count.

Two SSRF pre-check tests (`TestSafeFetchDoesNotRequireDNSAtSaveTime`,
`TestJITDefaultGroupMustBeRestricted`) fail on a machine whose resolver answers every name — this
one maps unknown hosts into 198.18.0.0/15, which the guard correctly treats as private. They assert
that an *unresolvable* host is not rejected at save time, so they need a resolver that can still say
no such host. Unrelated to this release and green on CI.
