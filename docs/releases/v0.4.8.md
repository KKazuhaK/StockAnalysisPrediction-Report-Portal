# v0.4.8 — comparing reports, and a place for assumptions to be reviewed

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema change.

## Added

Compare a report with another edition of the same analysis. A recurring
pipeline regenerates the same report for the same symbol over and over, so
what CHANGED is the news — a target price that moved, a risk that appeared, a
section that was dropped — and finding that by reading two documents side by
side is what nobody actually does.

It matches on the documents' own headings rather than on any schema, so it
works across every report type without knowing anything about their formats.
A '#' inside a fenced block is not a heading, and two sections sharing one
pair in order rather than collapsing. The endpoint accepts an arbitrary PAIR,
not just "this one and its predecessor": an internal edition against the
external one, or this quarter against the same quarter last year, are equally
valid questions. Both ids are scoped, and an unreadable report answers exactly
as a missing one does — otherwise it becomes a way to ask which ids exist.

A review queue for the assumptions a report rests on. tracking_items has been
written on every ingest since the v1 API shipped — what the report ASSUMED and
when that should be checked — and nothing had ever read it back except the
machine API. Assumptions nobody revisits are the difference between research
and opinion.

It is empty until the workflow sends the field, so the page carries the ingest
payload that fills it rather than saying "no data", which teaches nobody how
to get some. Filters are built from the values actually present, since the
contract lets a workflow use any vocabulary it likes, and a date is pulled out
of the free-text review point when it holds one — present means a real due
date, absent means fall back to age.

## Fixed

A re-run no longer erases a human's review. SetTracking clears and rewrites,
which is right for the content but reset every reviewed item to pending on
each regeneration — which would have made the queue worthless before anyone
noticed. A verdict now carries across, keyed on the exact text, so a REWORDED
assumption is a new one and starts pending: carrying "confirmed" onto a claim
that has changed would be worse than losing the review.
