# v0.4.47 — the hand-written reports stop being invisible

## Upgrade notes

From v0.4.46 — pull and restart. No schema changes.

One thing to know if you consume the webhook: **`report.ingested` now also fires for reports written
or edited in the browser**, and its payload has gained `version`, `author` and (on the v1 ingest
path) the same `created` flag it already had. Existing subscribers keep working; they will simply
start hearing about reports they were never told about before. See below.

## Fixed

Three gaps left by the editor that shipped in v0.4.42. Each is the same shape: the feature works,
and then stops at the edge of itself.

### A report a person wrote told nobody

A report pushed by a workflow fired `report.ingested` to every subscriber. A report written by hand
fired nothing — so a downstream index, a Feishu bot, or a nightly digest saw the machine's reports
and silently missed the ones a person wrote, which are usually the ones that exist *because* the
machine got it wrong.

It is the **same event**, deliberately, rather than a new `report.written`. A subscriber's contract
has been "a report arrived or changed" since ADR 0002, and minting a new type would leave every
existing subscriber missing hand-written reports until somebody noticed and subscribed again — which
is the bug, wearing a different name. For a subscriber that does want to tell them apart, the payload
now carries `version` (`manual` for hand-written), `author`, and `created`. The v1 ingest's payload
gained the same two fields so there is one shape and not two; `author` is empty for everything a
workflow produced, which is the honest answer.

An edit that rewrote no content — changing only the audience, say — fires nothing. That is the same
rule that decides whether a revision is filed, so the event stream and the edit history agree on what
counts as an edit rather than each having its own idea. Restoring an old revision does fire, because
it changes what the report says.

Deleting still fires nothing. There is no `report.deleted` for machine reports either, and adding one
only for hand-written ones would be a catalogue that is inconsistent in a new way.

### The hand-written reports were not a set you could ask for

You could write them and you could read them, one at a time, wherever they happened to appear. There
was no way to see them as a group — so "what have we written by hand this month?" meant scrolling.

浏览页的筛选栏 now has a **版本** filter. Hand-written reports *are* a version (ADR 0026), so the
filter is the whole answer, and it generalizes for free to the internal/external forms report
versions already allow — where a dedicated "manual reports" page would have needed a sibling page per
form.

The options come from your data and through your own read scope: a version nobody has written in is
not offered, and you are never shown the name of a version you cannot read, because a filter that
lists them becomes a directory of what exists. The control does not appear at all while only one
written form is visible — a filter whose every setting means the same thing is noise. And it can only
narrow: naming a version you were never granted returns nothing rather than reaching past your scope.

### Losing a draft took one click

The editor's draft exists nowhere but the textarea until you save. Closing the tab, hitting reload,
or clicking 返回 threw it away without a word — which makes it the one page in the portal where a
misclick destroys work that has no other copy.

Both of those exits now ask first. "Unsaved" means a save would write something different, not that
a control was touched, so reopening a report and leaving without typing still goes straight back.

Navigating away from elsewhere in the shell — a sidebar link — is still not guarded. Doing that
properly needs a router migration touching every route in the product, which is not a fair price for
one page; the two exits an author actually takes mid-draft are the ones covered, and the gap is
written down in ADR 0026 rather than left to be discovered.

### The ingest event named a version the report did not have

Adding `version` to the payload above echoed the field the request sent, and the store resolves an
empty one to the default — so the commonest ingest of all, the one that does not mention a version,
announced `version: ""` about a report the database stores as `"default"`. A subscriber comparing the
event against a later read had no way to reconcile that.

It now reports the version the row actually carries. An explicitly named version still travels
verbatim. The audit entry for the same ingest was echoing the raw field too, and now matches.

## Performance

The version filter's options are a `DISTINCT` over reports on the home feed, which is the busiest
endpoint in the portal, so it was measured rather than assumed: **24ms at 50,000 reports** on SQLite,
warm — beside the category scan already there (20ms) and the feed's own query (261ms). About 9% of
what the request already cost, and nearer 4ms at the size this portal actually runs at.

Left as a scan on purpose. An index on `version` would hold two or three distinct values across the
whole table: it would earn nothing on reads and charge every write, which is the same reasoning that
removed two other report indexes.

## Verification

Go build, vet, gofmt and the full Go suite (including the Postgres integration tests); web typecheck,
77 files / 528 tests, locale parity, and the SPA build.

The ingest event is tested against the stored row rather than against a constant: an ingest with no
version must announce whatever `GetNew` then reports for that report, so the two cannot drift apart
without failing. Echoing the raw field again turns it red.

The event is tested end to end through the handlers: a newly written report reaches a real subscriber
with its id, identity, version and author; an edit is announced as an update rather than a creation;
and a save that changed no content is proven to fire nothing. Both directions were confirmed by
mutation — removing the announce, and announcing unconditionally.

The version filter is tested for what it returns, for what it offers, and for what it must refuse: a
reader granted one version and not the other gets nothing when naming the one they lack, and is not
told it exists. Removing the predicate and offering the whole registry instead of what is present and
visible both turn the tests red.

The unsaved-work guard is tested at all three of its moments — clean page leaves silently, a typed
draft blocks both exits, a saved draft stops blocking — and a changed title counts as much as a
changed body. Removing the listener, removing the back-button guard, and forgetting to refresh the
snapshot after a save each fail a different test.
