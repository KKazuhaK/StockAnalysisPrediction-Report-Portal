# v0.4.47 — prices on the home cards, a minute-by-minute chart, and a source you can switch on

## Upgrade notes

From v0.4.46 — pull and restart. No schema change, no migration. The two new settings are ordinary
`meta` rows an older build ignores, and both ship with a default that reproduces what v0.4.46 did,
with one deliberate exception below.

**The home page now shows a live price on every card that names a stock**, and that is on by default
because it is what was asked for. It costs **one** upstream request per page view, whatever the page
holds — not one per card. It also means the codes currently on screen are sent to a third-party
vendor on every home page view, which is a small outward disclosure and therefore a switch:
管理 → 行情源 → 首页卡片行情. Off, the home page sends nothing anywhere and looks exactly like
v0.4.46's.

**Yahoo Finance is compiled in and switched OFF.** Nothing calls it until an operator adds `yahoo` to
the source order. See *New* for what turning it on buys and what it costs you to depend on.

Rolling back to v0.4.46 removes the two intraday ranges and the card prices. Nothing stored needs
undoing.

## Fixed

**Enabling a source that serves US dailies produced no US chart.** This is the one that mattered, and
it was a modelling error rather than a typo: `quoteMarket.history = false` meant *"Tencent has no
usable US daily series"* and the range resolver read it as *"the US has no daily interval"*. So
`range=6m` on a US symbol degraded to a snapshot **before any source was consulted**, and the chain
for (US, daily) — the entire reason a third source exists — was never asked. Enabling Yahoo changed
nothing on screen while 管理 → 行情源 advertised a US daily column it could not deliver.

A range now says what the *reader* asked for; the enabled sources say what this deployment can
*serve*, and a request degrades only when the answer is genuinely nobody. The panel's honesty is now
a test: it walks its own capability columns and requires that every pair it advertises is reachable
by a range a reader can actually pick.

**A code the portal understood but a vendor cannot spell counted against that vendor's health.** Hong
Kong codes not starting with a zero have no Yahoo spelling. The resolver did not know that, so the
request reached a fetcher that refused it before any HTTP call — and the refusal, a fact about *our
own* code, was recorded as a vendor failure and answered 503 for a gap no retry closes. A source now
declares which codes it can spell, using the same function its fetcher uses, so the two cannot drift.
Such a code degrades to a price from another source and the vendor's counters stay clean.

**A batch every line of which the drift gate refused looked like a vendor outage.** A home page whose
only card is a suspended or delisted stock is exactly that batch, and it made the consecutive-failure
streak an operator reads climb on every page view while Tencent was answering perfectly — the direct
opposite of what those counters are for. It is now neither a success nor a failure. The vendor half
is still enforced: a body carrying no line for *any* symbol asked about is an error from the parser,
so a source answering rubbish all day cannot look healthy by falling in here.

**The day-range drift check ran on one of the three parsers.** Check 5 — the last price has to lie
inside the day's own high and low — was in the single-symbol Tencent path and in neither the batch
path nor the new one. It now runs at the end of all three, still skipping a stock whose high and low
are both zero, which is what a suspended stock reports.

**A 分时 chart could be cached for five minutes.** The TTL was chosen by asking the session first, so
a one-minute series on a market the vendor still reported as closed — which is every market at 09:31
— took the five-minute closed-market cache. The interval is now asked first: a one-minute series gets
a one-minute cache whatever the session says.

## New

**Live prices on the home cards.** Price, move and the vendor's own percentage, in 红涨绿跌 — the same
colours as the reading page, deliberately, because the same reader crosses from one to the other in a
click.

The feed never waits on it. The report list renders first and prices drop into a line that was
already reserved for them, so a late answer cannot re-flow a grid somebody has started reading. A
dead vendor, a refused request, a switched-off feature and a response this build cannot read all look
identical from the page: no price, no banner, no spinner. There is nothing honest to say about a
decoration that did not arrive.

A page of 60 codes asks for the first 50 rather than sending 60 and earning a refusal that would cost
every card its price.

**分时 and 5日.** Two intraday windows beside the four daily ones: about 400 one-minute points for a
session, about 330 five-minute ones for a week. The chart draws a line rather than candles for these
and labels the axis with times instead of dates — and it is *told* which it was handed rather than
guessing from the range, because a range switch keeps the old bars up for the whole round trip and
guessing would draw three months of candles under a clock.

The intraday cache has its own TTL (default 60s, floor 15s, clamped on save and on read like the
other two), because a five-minute cache on a one-minute chart is a stale price wearing a fresh label.

**Yahoo Finance, compiled in and OFF.** It exists for one measured hole: `AAPL` over six months
returns **128 daily bars** from Yahoo and **two rows fifteen years apart** from Tencent. It ships
disabled not out of doubt about the parser but because the endpoint is undocumented and unlicensed —
no contract, no changelog, no availability commitment, and no terms this repository can point you at.
Whether your deployment depends on that is your call, not the build's. The same shape as ADR 0017's
cleanup targets and the GeoIP loop. Add `yahoo` to the source order; there is no second flag.

It gets its own drift gate, because its response is a different shape and Tencent's positional checks
say nothing about it. Three traps were measured and each returns a plausible wrong answer rather than
an error:

- `chartPreviousClose` is the close before the **requested range**, not yesterday's. For AAPL on one
  afternoon it is 328.21 at 1 day, 319.70 at 5 days and **262.52 at 6 months** — enough to render
  Apple at **+21.9%** on a day it fell **2.51%**. It is not a field of our decoded type at all.
- `00700.HK` answers **HTTP 200 with a well-formed body for a different instrument**: a mutual fund
  on "YHD" with a null currency and a June 2019 timestamp. Hong Kong on Yahoo is four digits. Three
  independent layers refuse it.
- Prices are JSON floats — `328.30999755859375` is how the wire spells 328.31. They are decoded as
  `json.Number` and parsed from the decimal string into 分. No float64 touches a price.

**管理 → 行情源 separates daily from intraday.** With a US-daily source available, the choice is no
longer "which vendor" but "which vendor for what", so the capability columns split. An empty cell is
a real answer and is shown as one.

Design notes in [ADR 0031](../adr/0031-quote-capabilities-intraday-and-home-cards.md).

## Verification

Go build, vet, gofmt, and the whole `internal/app` suite including under `-race`. Web typecheck,
**683 tests across 87 files**, locale parity and the SPA build. No new dependency in `go.mod` or
`web/package.json`.

Two adversarial reviews ran over this and proved their findings by mutation rather than by reading:
**24 mutations** were re-applied afterwards to confirm each fix is actually held by a named test,
and every one of them turned a specific test red. The reviews found the US-chart defect above, which
no test had caught because the specification itself was wrong about it, and eleven claims that
existed only as comments — among them that a snapshot shares one cache slot across every range (four
ranges on a market with no history cost four upstream calls and four cache entries without it), that
the cache returns the *freshest* entry rather than whichever Go's randomised map order reaches first,
and that a batch spanning four markets never blames a vendor for a market it did not declare.
