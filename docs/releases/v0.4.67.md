# v0.4.67 — spreadsheet-style batch entry

From v0.4.66, pull and restart. No database schema change or migration is required.

## Batch execution

- Batch data now opens in a bounded spreadsheet instead of a single CSV text area. Operators can
  edit cells, add or remove rows, and paste multi-row blocks directly from Excel or Google Sheets.
- Required cells are validated before submission, with invalid rows called out inline. Empty
  placeholder rows are ignored rather than submitted.
- The CSV workflow remains available as a synchronized mode, including file upload and download.
  Imported files must declare every workflow input column before they can run.
- Large workflows scroll inside the table in both directions and never widen the page. Run timing,
  concurrency, retries, priority, notifications, and the submit action stay in a dedicated right
  rail on desktop; narrow screens stack the two areas.

## Run analysis

- Long parenthetical input guidance no longer changes label height or misaligns neighboring fields.
  The form shows a compact field name plus the localized optional marker, with the full guidance
  behind a circular help button.
- Input and run-settings rails scroll independently on desktop, so the settings remain visible while
  a long workflow form is reviewed. Mobile keeps the natural single-column scroll.

## Validation

Frontend type checking, the complete frontend test suite, the production frontend build, repository
build/vet/tests, and browser checks for wide-table overflow, spreadsheet paste, CSV synchronization,
and independent modal scrolling pass.
