# v0.4.33 — a workflow that asks for a file can be given one

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema changes and nothing to run by hand. Rolling back
to v0.4.32 is clean: the run form falls back to text boxes for every input, which is what it did
before, and a workflow that declares a file input simply cannot be run from the panel again.

Nothing changes for a workflow whose inputs are all text. The run form renders those exactly as it
did, and the payload it posts is byte-for-byte the same.

## Added

**The run form can now upload files.** A Dify workflow that declares a `file` or `file-list` input
gets a picker instead of a text box. The browser sends the file to the portal, the portal forwards
it to that target's own Dify instance with that target's key, and the run carries the returned file
id. The key never reaches the browser, and the file is not stored here — the portal is a conduit,
not a second copy.

The caps are Dify's own and both sides hold them: 15MB per file, ten files per run. The browser
refuses an oversized or excess file before the upload starts, so the answer is immediate rather
than arriving after a 15MB round trip. The server refuses the same run outright rather than
truncating it — a run that quietly dropped an attachment would produce a report that looks like it
cited evidence it never saw.

**The run form renders each input as the type it was declared.** Until now every input was a single
line text box, whatever Dify said it was. A paragraph gets a textarea, a number gets a number
field, a select gets its choices, and a file gets the picker. The type was already known — Dify
reports it, and the portal has been reading it since the target was first discovered — it just was
not being passed to the form.

## Fixed

**A select input had no choices.** The input declaration sent to the run form carried the field's
key, label and required flag, but not its options, so a workflow's select arrived as a text box
with no hint of what it would accept. The options now travel with the declaration.

## Notes

Batch runs cannot carry files. A CSV cell holds a string, and a file is not one; a batch row that
names a file input is ignored the same way an unfilled input is. Single runs from the panel are the
only surface that uploads.
