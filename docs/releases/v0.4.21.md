# v0.4.21 — pull a workflow's parameters back; the compare button works

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema change.

## Fixed

**The compare button did nothing.** `CompareModal` was imported, the button set the state that
selects a report to compare, and nothing ever rendered the modal — so the control had been inert
since the day it shipped. It opens now.

It was also the only control in that header at `size="small"`, a size smaller than the export and
reading-settings buttons beside it.

**A failed parameter probe wiped the parameter list.** Re-probing in the target editor replaced the
inputs with whatever came back, and an empty list is what comes back when Dify answers but
`/parameters` does not. An admin who had typed their columns in by hand — which is exactly what the
editor tells them to do when discovery fails — lost them by pressing the button that was supposed to
help. A probe that could not read the list now leaves the list alone.

## Added

**Pull a Dify target's parameters back from Dify**, per row or all at once, from the target list —
no more opening the editor one target at a time to find out whether a workflow changed upstream.

It previews before it writes, the same way a cleanup does, because a target's parameter list is how
every future run of it is submitted. The preview names each kind of change separately — added,
removed, required-flag flipped, reordered, app kind changed — since "it differs" is not something
anyone can approve.

**The target's name cannot be overwritten.** Not "the client does not send one": the apply endpoint's
request has nowhere to put a name. The report subtype, the stock-code input, the address and the
credential are equally local and equally untouched — apply writes the parameter list and the app
kind, and re-marshals everything else exactly as it read it. Dify's own name is shown beside the
local one, and only when they differ, so an admin can confirm the key still points at the workflow
they think it does.

Two cases get more than a tag:

- **The stock-code input disappeared from the list.** That does not fail a run — it silently turns
  off same-day reuse (ADR 0022), so the portal pays to regenerate reports it already has. A silent
  regression that costs money gets an alert.
- **Dify answered but `/parameters` did not.** Nothing is proposed and the row cannot be selected.
  The apply endpoint refuses an empty list outright, so the bug fixed above cannot come back through
  the new path.

## Changed

**One "Export ▾" menu at every width.** The three export buttons collapsed into a menu on a phone
and stayed separate on a desktop, where four labelled buttons pushed the card header into a wrap
that had the report title competing with its own toolbar. They are one thing you do to a report, so
they read better as one control anyway.

## Verification

Go and web suites (321 web tests, 11 new), vet, gofmt, both builds, and `scripts/e2e_check.py`.

One of the new tests was green before the fix and had to be corrected first: jsdom reports no
breakpoints at all, so `useBreakpoint().md` is false and a test about the *desktop* layout passed
against the very code it was written to reject. It mocks a desktop width now, fails on the old code,
and passes on the new.
