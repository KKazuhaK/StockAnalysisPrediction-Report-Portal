# v0.4.6 — the leftovers, closed

Everything still on the list after v0.4.5: two configuration traps, an unshipped
admin action, the last dependency advisory, and the documentation that only
existed inside git tags.

## Upgrade notes

From v0.4.3, v0.4.4 or v0.4.5 — pull and restart. No schema change. From
v0.4.1 the portal still refuses to start and explains why.

## Added

An admin can see and revoke an account's identity-provider binding. The store
could do both from the day SSO shipped and nothing could reach either, so the
only way to cut a stale link was to delete the account. Revoking matters on
its own: a binding outlives the person's account at the IdP, and while it
stands, whoever the IdP later issues that subject to signs in as this account.
Unlinking keeps the account, returns it to local sign-in and ends its
sessions. The users list now reports which accounts are federated at all —
it never did, which is the same blind spot that had the page offering password
resets to accounts that have no password.

## Fixed

Two configurations that could not work are now refused rather than saved.
Refusing password login while self-service registration is open mints accounts
nobody can use — registration creates a local password account and the policy
turns exactly that away. And refusing it with no local-password admin left is
a locked door with the key inside, since a federated admin is nilled out
before bcrypt and never reaches the exemption.

"Inherit the system default — the system default" said it twice. Some sources
have no value worth naming. Found by mounting the component with fixture data
and reading the labels, which also confirmed the other four read correctly.

## Removed

react-router-dom. The last open advisory (GHSA-qwww-vcr4-c8h2) had no fix in
the 7.x line; v8 folded the DOM package back into react-router, so this is one
dependency swap and an import rewrite. Verified past the typecheck, because
routing is what typechecks and then breaks: on the real binary, /login renders,
a pushState to /stock/600519 matches the route and redirects through the auth
gate, and the /register deep link resolves through the SPA fallback. (A
permanently spinning dev server after the swap was Vite's stale
dep-optimisation cache, not a regression.)

The absolute path baked into scripts/e2e_check.py, which meant the harness ran
only on the machine it was written on.
