# v0.4.17 — the IP database is a feature, not a URL box

## Upgrade notes

From v0.4.3 or later — pull and restart. No schema change; the new settings are
ordinary rows in the settings table and default to off.

The IP database is configured under **Settings → General** now, not on the audit
page. If you set a download URL in v0.4.16 it is still there, as the "Custom URL"
source.

## Fixed

**The action filter offered one option on a freshly upgraded portal.** It was
built from `SELECT DISTINCT action` over the rows that exist, so it listed only
what had happened to happen — and an admin could not tell "this is not recorded"
from "this has not happened yet". A portal that had only ever served report reads
showed a log that looked like it records one thing.

It offers the whole vocabulary this build can write, plus anything present in the
data that is not in it — so a row written by an older build, or by a build that
has since retired an action, stays reachable. A test keeps the list and the
constants from drifting apart, which is the same failure seen from the other
side: an action written but never offered would be invisible in the console.

## Changed

**The IP database has a real configuration surface**, modelled on the sibling
panel the owner pointed at. Four of the differences from v0.4.16 are behavioural,
not cosmetic:

- **The download is validated before it swaps.** A truncated response, or an HTML
  error page served with a 200, would otherwise overwrite a working database with
  something unreadable and the feature would go dark until somebody noticed. The
  temp file is parsed as a real `.mmdb` first; a test installs a working database,
  serves rubbish, and checks the working one survives.
- **The swap happens under the reader's lock with the live reader closed first**,
  because a memory-mapped file cannot be renamed over on Windows while a lookup
  holds it. The temp file carries the PID — the in-process single-flight does not
  span processes, and during a rolling restart two of them share the data volume.
- **The URL is constructed, not typed.** Source, edition and credential. Pasting a
  whole URL is how people end up with the wrong edition, a missing suffix, or a key
  in their clipboard history. Four sources — MaxMind, DB-IP, IPinfo, custom — and a
  test walks the list to prove each is actually handled, because a source that
  saves and then fails only at download time is exactly the drift that list exists
  to prevent.
- **Both gzip shapes**, told apart by the tar magic in the *decompressed* stream
  rather than by a file extension a redirect can make a liar of. DB-IP needs no key
  and publishes month-stamped files with no "latest", so the current month and the
  previous one are both tried; the previous-month helper is written as "the 1st,
  minus a day", because `AddDate(0,-1,0)` normalises the 31st back into the same
  month and would make the fallback identical to the URL that just failed.

**Automatic updates**, because MaxMind's licence requires the data to be refreshed
at least every 30 days and leaving that to a human is leaving it to a licence
breach. The loop ticks every minute and compares elapsed time rather than sleeping
for the interval, so turning it on — or changing it — takes effect within a minute
instead of at the next restart.

Plus an enable switch, a picker over the installed databases showing what each one
is and when it was built, the credential as "saved — leave blank to keep it", and
the EULA and attribution notes.

**It lives under Settings → General**, beside the public URL, for the same reason
that one moved there in v0.4.7: it describes the *deployment* rather than
belonging to the one feature that displays its output. The audit page keeps a
single line — locations off, which database is answering, or none installed and
where to configure one — which is the sentence somebody needs at the moment they
notice a row has no location.

## Verification

Go and web suites (302 web tests), vet, gofmt, both builds, and
`scripts/e2e_check.py`.

One robustness fix surfaced by the move: the section fetches its own status inside
a page that fetches other things, and a response without `status` threw inside the
promise, taking the rest of that page's effects with it. It leaves the section
absent instead — which is what it does when no database is installed anyway.
