# v0.4.45 — settings that were read and never written

## Upgrade notes

From v0.4.44 — pull and restart. No schema changes. Every setting below keeps the value it has been
behaving as all along, so nothing changes until you go and change it.

One thing worth knowing: **an authenticator entry enrolled before this upgrade keeps its old label.**
See below.

## Fixed

Six settings had a reader, a default and a comment describing the choice an operator could make —
and nothing anywhere able to make it. A setting in that state is not configuration; it is a constant
with a misleading name, and the only way to notice is to go looking for the writer.

**Two-factor enrolments ignored your portal's name.** The authenticator label read a key nothing in
the repository has ever written, so every entry landed under "Report Portal" no matter what the
branding said. It now reads the same `site_title` the shell, the PWA manifest, the login page and
the email sender read.

Authenticator entries are effectively permanent, so anyone who enrolled before this keeps the old
label until they re-enrol. That is not worth forcing on people, but it is worth knowing why two
colleagues' phones disagree.

**The run form offered twice the concurrency the server would honour.** The per-job ceiling every
requested concurrency is clamped to has been read since the batch engine shipped and could never be
set, so it sat at its built-in 10 — while the recurring-task form's picker went up to 20. Choosing
15 got you 10, silently.

It is now on 管理 → 运行队列, and the picker asks the server for its ceiling rather than carrying a
number of its own.

**SSO could not be pointed at an IdP on your own network.** The SSRF guard refuses private addresses
by default, because an IdP URL is admin-supplied and points wherever it says — and its own comment
calls the exception "a setting", because a self-hosted IdP is the common case. There was no way to
set it. 管理 → 单点登录 now has the switch, above the provider tabs because it is not a property of
any one provider: it widens what *every* outbound SSO call may reach. Off by default, anything but
an explicit yes reads as off, and turning it on is recorded in the audit log.

**The app market could not be repointed.** The constant behind the index URL has promised since the
market shipped that an admin could change it. The field is now on 管理 → 应用, it shows the address
in force, and leaving it empty returns to the built-in index — so undoing does not require knowing
the default URL by heart. A saved address goes through the same SSRF guard the fetch itself uses.

**Two values the server computes were on no screen at all.**

A job whose status is *running* is not necessarily running *here*: after a restart the row survives
while the goroutine driving it does not, and the portal reconciles it by polling instead. The server
has always computed which of the two it is; the job drawer now says so, which is the difference
between "this is stuck" and "there is nothing here to stop".

And the run-quota chip said "2 of 5 left today" without ever saying when the 5 comes back. The
server has always sent the exact instant; it is now the chip's tooltip — where it belongs, since it
is the answer to a question you only have once you have hit zero.

**Six refusals reached English and Traditional Chinese admins in Simplified Chinese.** The portal
answers a rejection with a machine-readable code precisely so the browser can translate it, and six
codes had no string in any bundle — so the fallback ran, and the fallback is the server's own
sentence, written before the browser's language is known.

## Changed

**`GET /api/v1/reports` documents the `version` field it has always returned.** Report versions
shipped in v0.4.39 and every v1 read has carried the field since; the OpenAPI schema did not list
it, so a machine consumer generating a client from the spec dropped it.

## Verification

Web typecheck, 520 tests across 76 files, locale parity, and the SPA build. Go build, vet, gofmt and
the full Go suite.

Each newly writable setting is tested end to end — that the default is what the portal was already
behaving as, that saving takes, that an out-of-range value is refused without disturbing the working
one, and for the SSO switch that anything but an explicit yes fails closed. The market index is
additionally tested to refuse a private address, so a stored value cannot become a probe of the
host's own network.

The translation gap is now a test rather than a discovery: it scans every `jsonErrorCode` the server
can answer with and requires a string in all three bundles, and it refuses to pass if the scan finds
implausibly few codes — a check that silently finds nothing is the failure it exists to prevent. It
was confirmed by deleting one string and watching it fail.
